# 5.0 第 5 部分简介：UI/UX 设计

本部分讲的是软件与使用它的人相遇的地方。这涵盖了很多内容：揭示用户需求的研究、呈现这些需求的界面和[设计系统](https://en.wikipedia.org/wiki/Design_system)、引导行动的文字、让每个人都能使用的[无障碍](https://en.wikipedia.org/wiki/Accessibility)和语言支持，以及把这一切交付到真实浏览器和设备这个混乱现实中的前端工程。人们很容易把这一切都当作最后才加上去的装饰。请抵制这种想法。这里正是所有上游工作最终触达用户、或功亏一篑的地方，而它的成败早在最后一块屏幕被打磨完成之前，就已经被决定了。

对于大型团队而言，产品设计其实是一个协调问题。当数十个小队向同一个共享产品交付功能时，各自独立的决策会堆积成一团混乱：重复的流程、相互矛盾的术语、不一致的组件，以及一条没有人负责的语言流水线。本部分每一章给出的解决办法都有着相同的形态。把一次性的决策变成共享的、受治理的资产，比如用户画像、一套设计系统、一套内容策略、一套[国际化](https://en.wikipedia.org/wiki/Internationalization_and_localization)（i18n）框架、组件库和性能预算，这样众多团队各自独立开展的工作最终仍能汇聚成一种连贯一致的体验。

企业和政府把这一切的重要性进一步抬升。企业软件往往拥有被"锁定"的用户，他们为糟糕的设计所付出的代价体现在培训、出错和支持负担上，而不是转身离开。政府服务面向的是全体公众（包括身处危机之中的人、使用旧设备的人、数字素养较低的人，或者没有替代服务提供方的人），因此设计质量成了一个关乎公平和公民信任的问题。在这里，无障碍不是一个锦上添花的选项，而是一项法律强制要求：公共机构在法律上被要求构建残障人士也能使用的软件，而[通俗语言](https://en.wikipedia.org/wiki/Plain_language)和语言可及性方面的义务也常常同样具有法律效力。

## 本部分的章节

- **5.1 UX 基础**：让一个组织能够基于证据而非猜测做出产品决策的研究、用户建模和设计思维实践，为每个团队提供同一张用户地图。
- **5.2 UI 设计与设计系统**：塑造人们所看到和触及之物的技艺，以及让数千个屏幕在众多团队之间保持一致的、共享且受治理的标记（token）、组件和模式体系。
- **5.3 无障碍**：构建残障人士能够感知、操作、理解和使用的软件，将其同时视为一项法律义务、一项伦理义务，以及单纯的优秀设计。
- **5.4 内容与沟通设计**：以通俗语言和一致的语气，塑造一个产品用来帮助人们采取行动的文字、信息和沟通内容，因为文字本身就是一种界面。
- **5.5 国际化与本地化**：让软件能够适配任何语言和地区的架构，以及为每个语言环境进行翻译和文化适配的工作流程。
- **5.6 前端工程**：为一个你无法完全掌控的环境构建面向客户端的那一层，需要关注框架的长期可维护性、渲染策略、性能和韧性。
- **5.7 移动应用开发**：为移动设备构建应用，涵盖原生、跨平台和渐进式 Web 方法；平台设计指南；离线、电量和碎片化方面的限制；应用商店分发；以及移动端的安全和无障碍。

- **5.8 设计研究与可用性测试**：通过生成式和评估式研究、针对每个问题选用正确的方法、做得好的可用性测试、具有代表性的招募，以及真正能够改变决策的综合分析，来降低构建出错误产品的风险。
- **5.9 服务设计**：设计一个人跨越各个渠道、经历一段时间所体验到的整个服务，涵盖前台和后台，使用服务蓝图和旅程地图，并让整个组织围绕这项服务（而不仅仅是单一屏幕）保持一致。
- **5.10 数据可视化设计**：为问题选择正确的图表形式，诚实地编码数据，运用图形表达的卓越技艺、无障碍且对色盲友好的配色方案，以及清晰的注释，让一张图表能够为决策提供信息，而不是误导决策。

## 这些章节如何相互关联

这些章节构成了一条从理解到交付的单一主线。UX 基础（5.1）确立了用户是谁、他们试图完成什么任务。UI 与设计系统（5.2）为这种理解赋予一致的视觉形式。内容设计（5.4）提供承载这一切的文字。前端工程（5.6）把成果交付出去。无障碍（5.3）和国际化（5.5）不是独立的阶段，而是贯穿其他所有章节的品质：一种无障碍、可翻译的体验，是从一开始就被设计进共享组件、内容模式和代码之中的，而绝不是事后附加上去的。第 5.3 章尤其依赖第 5.2 章在每个组件中一次性解决无障碍问题，也依赖第 5.6 章通过语义化、基于标准的标记语言把它保留下来。

本部分的内容也贯穿整本指南。这里"资产优先于一次性方案"的模式，与第 8.4 章（平台工程与开发者体验）的共享平台思路相呼应，而第 1.1 章和第 1.4 章中的价值观与工作方式，则确立了让设计一致性得以实现的组织条件。无障碍检查、视觉回归检查和性能预算检查都应当纳入第 8.1 章（CI/CD 与交付）所述的交付流水线中，这样质量才能在每一次变更时得到强制执行，而不是在上线前夕才被审计一遍。而前端性能所依赖的真实用户监控（从实际用户的设备和网络中收集的性能数据），则与第 9.2 章的可观测性实践直接相连。做得好的话，本部分的工作正是让其他章节所描述的系统，真正能够为它们本应服务的人所使用的关键所在。
